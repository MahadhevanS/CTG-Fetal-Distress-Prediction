# Comprehensive Data Preprocessing Plan

## 1. Objective
This document outlines the end-to-end data preprocessing pipeline for the CTG Fetal Distress Prediction framework. It addresses two distinct data modalities while explicitly handling the severe class imbalance typical of fetal distress datasets and preparing the ground for knowledge infusion.

### Dataset Roles
The two datasets are processed independently:
- **CTU-CHB (Time-Series)**: Serves as the **primary dataset** for temporal representation learning and predicting the primary clinical outcome (fetal distress/acidemia).
- **UCI SisPorto (Tabular)**: Serves as an **auxiliary structured dataset** for validating our programmatic feature extraction, establishing classical ML baselines, and external validation. It is *not* used as a primary knowledge source for the neural network.

## 3. Dataset-Specific Processing

### 3.1 UCI Cardiotocography Dataset (SisPorto Features)
- **Nature**: 2,126 records of 21 pre-extracted features generated by the SisPorto 2.0 system.
- **Preprocessing Steps**:
  1. Load data via `pandas`.
  2. Handle missing/NaN values via median imputation.
  3. **Feature Scaling**: Fit Z-score standardizer on the **training data only**, and apply it to the validation/test sets to prevent data leakage.
  4. **Target Mapping**: Retain the 3-class label (Normal, Suspect, Pathologic) strictly for **FIGO auxiliary supervision** and evaluation benchmarks. (Note: "Suspect" does not equate to distress; thus, this dataset is not used for the primary binary distress task).

### 3.2 CTU-CHB Intrapartum Dataset (Time-Series)
- **Nature**: Continuous FHR and UC signals (`.dat`/`.hea`), paired with clinical metadata.
- **Clinical Metadata Retention**: Extract and retain Gestational Age, Parity, Maternal Age, Stage of Labor, Delivery Mode, and Fetal Sex for future multimodal expansion.
- **Primary Clinical Target**: Early fetal distress/acidemia, defined clinically by an umbilical artery pH $\leq$ 7.15 (representing a widely accepted threshold for moderate-to-severe acidemia).

---

## 4. Signal Processing & Quality Assessment (CTU-CHB)

### 4.1 Signal Quality Assessment (SQA)
Prior to interpolation, recordings must pass an SQA filter to ensure clinical validity.
- Calculate the percentage of valid samples (FHR > 0).
- Compute the Signal Loss Ratio and Artifact Ratio.
- **Window Rejection**: Any temporal window with **> 30% missing signal** is discarded entirely to prevent neural network hallucination.

### 4.2 Interpolation & Artifact Removal
- **Missing Data**: Interpolate short signal dropouts (< 15 seconds) using cubic spline interpolation.
- **Spike Removal**: Remove unphysiological FHR spikes (> 25 bpm/sec change).

### 4.3 Filtering & Resampling
- **Resampling**: Standardize the sampling frequency to **4 Hz** to ensure uniform temporal resolution across all recordings before windowing.
- **Filtering**: Apply a **2nd to 4th-order low-pass Butterworth filter** (cutoff frequency ~1.5 Hz) to smooth high-frequency noise. Higher-order filters (e.g., 10th order) are avoided to prevent ringing artifacts.

---

## 5. Clinical Feature Extraction & Rule Engines

### 5.1 Iterative Baseline Estimation
- **Rule**: Hospitals do not use a simple rolling mean. 
- **Implementation**: We employ robust iterative baseline estimation (or an asymmetric least squares approach) that explicitly excludes accelerations, decelerations, and large signal excursions to mimic true FIGO clinical interpretation.

### 5.2 Deceleration Classification
- **Detection**: Decelerations cannot be identified by simple peak detection.
- **Analysis**: We extract Amplitude, Duration, Onset, Recovery, Shape, and strictly analyze the temporal **Relationship to UC** (Uterine Contractions) to accurately differentiate between *Early*, *Late*, *Variable*, and *Prolonged* decelerations.

### 5.3 Knowledge Rule Engine (FIGO)
- Run the algorithmically extracted features through a programmatic rule-engine corresponding strictly to FIGO guidelines. NICE guidelines are reserved exclusively for post-training evaluation.
- **Derived Supervisory Labels**: The outputs of this engine (Normal, Suspicious, Pathological) are stored as **pseudo-labels** (Auxiliary Targets), NOT "ground truth," as they are programmatically derived, not manually annotated.

### 5.4 Explainability Preparation
- Store the explicitly calculated Baseline, Variability (STV/LTV), Deceleration metrics, and UC peaks alongside the window timestamps. These will be crucial for the post-hoc explainability framework and clinician-facing UI.

---

## 6. Windowing Strategy (Time-Series)

### 6.1 Size and Stride
- **Sliding Window**: Extract **20-minute consecutive windows**. This is clinically justified, as FIGO interpretation guidelines explicitly require at least 20 minutes of tracing to accurately assess baseline and variability.
- **Stride**: 5-minute stride for normal cases.

### 6.2 Prediction Horizon Labeling
- Every window from a Pathological patient should *not* automatically receive a "Distress" label, as early windows may represent healthy states, leading to weak supervision.
- **Implementation**: Only windows occurring within a **clinically relevant prediction horizon** (e.g., 30–60 minutes prior to delivery/intervention) are assigned the terminal pH outcome label.

---

## 7. Splitting, Imbalance, and Training Optimization

### 7.1 Patient-Level Stratified Splitting
- Split the dataset (Train 70% / Val 15% / Test 15%) strictly at the **patient level**.
- **Data Leakage Prevention**: We guarantee that no overlapping windows from the same patient appear across the Train, Validation, and Test sets.

### 7.2 Class Imbalance Handling (Training Set ONLY)
Class imbalance is addressed using patient-level stratified splitting, overlap-based minority window generation (e.g., 1-minute stride for Pathological vs 10-minute stride for Normal), class-weighted loss functions (**Weighted Cross-Entropy** / **Focal Loss**), and mild physiological data augmentation (Gaussian noise, amplitude perturbation). 

**No synthetic CTG waveforms or features are generated** (e.g., via SMOTE) for the primary deep learning framework, ensuring that all training samples retain strict clinical authenticity and physiological plausibility. For any comparative baseline experiments (e.g., Random Forest or SVM) running strictly on the structured SisPorto dataset, SMOTE may be applied exclusively on the training partition.

### 7.3 Model Input Normalization
- To stabilize temporal deep learning gradients, the model input will utilize **Baseline Corrected FHR** (i.e., `FHR_signal - FHR_baseline`) rather than absolute FHR, directly embedding the relative variation into the neural representation.

### 7.4 Calibration
- Medical AI demands reliable confidence scores. Post-training, the model outputs will undergo **probability calibration** (e.g., Temperature scaling or Platt scaling) to ensure output logits reflect true clinical risk probabilities.

---

## 8. Multi-Task Label Generation

Each 20-minute input window is paired with a comprehensive label vector containing:
1. **Clinical Outcome Target (Primary)**: Terminal clinical outcome (pH $\leq$ 7.15), applied strictly within the valid prediction horizon.
2. **Derived Supervisory Targets (Auxiliary)**: The algorithmically extracted FIGO class, Baseline FHR, Variability, and Deceleration classifications specific to that exact window.
