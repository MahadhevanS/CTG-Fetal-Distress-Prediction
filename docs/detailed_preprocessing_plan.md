# Comprehensive Data Preprocessing Plan

## 1. Objective
This document outlines the end-to-end data preprocessing pipeline for the CTG Fetal Distress Prediction framework. It addresses two distinct data modalities while explicitly handling the severe class imbalance typical of fetal distress datasets and preparing the ground for knowledge infusion.

### Dataset Roles
The two datasets are processed independently:
- **CTU-CHB (Time-Series)**: Serves as the **primary dataset** for temporal representation learning and predicting the primary clinical outcome (fetal distress/acidemia).
- **UCI SisPorto (Tabular)**: Serves as an **auxiliary structured dataset** for validating our programmatic feature extraction, establishing classical ML baselines (Random Forest, XGBoost), and external validation. It is *not* used as a primary knowledge source for the neural network.

## 3. Dataset-Specific Processing

### 3.1 UCI Cardiotocography Dataset (SisPorto Features)
- **Nature**: 2,126 records of 21 pre-extracted features generated by the SisPorto 2.0 system.
- **Implementation**: [`uci_pipeline.py`](file:///c:/Users/ELCOT/Desktop/CTG-Fetal-Distress-Prediction/src/preprocessing/uci_pipeline.py)
- **Preprocessing Steps**:
  1. Load data via `pandas` from `.xls` or `.csv`.
  2. Handle missing/NaN values via median imputation.
  3. **Feature Scaling**: Fit `StandardScaler` on the **training data only**, and apply it to validation/test sets to prevent data leakage. Saved as `uci_scaler.joblib`.
  4. **Target Mapping**: Retain 3-class label (Normal=0, Suspect=1, Pathologic=2). Binary label maps Pathologic=1, Normal=0, excluding Suspect rows.

### 3.2 CTU-CHB Intrapartum Dataset (Time-Series)
- **Nature**: Continuous FHR and UC signals (`.dat`/`.hea`), paired with clinical metadata.
- **Clinical Metadata Retention**: Extract and retain Gestational Age, Parity, Maternal Age, Stage of Labor, Delivery Mode, and Fetal Sex for future multimodal expansion.
- **Primary Clinical Target**: Early fetal distress/acidemia, defined clinically by an umbilical artery pH $\leq$ 7.15 (representing a widely accepted threshold for moderate-to-severe acidemia).

---

## 4. Signal Processing & Quality Assessment (CTU-CHB)

### 4.1 Signal Quality Assessment (SQA)
Prior to interpolation, recordings must pass an SQA filter to ensure clinical validity.
- Calculate the percentage of valid samples (FHR > 0).
- **Window Rejection**: Any temporal window with **> 30% missing signal** is discarded entirely to prevent neural network hallucination.

### 4.2 Spike Removal & Interpolation
- **Spike Removal**: Remove unphysiological FHR rate changes (> 25 bpm/sec, i.e., > 6.25 bpm per sample at 4 Hz) using `remove_spikes()`. Spikes are zeroed out so they are cleanly reconstructed by spline interpolation.
- **Missing Data**: Interpolate short signal dropouts (< 15 seconds / 60 samples) using cubic spline interpolation (`interpolate_missing`). Gaps > 15 seconds remain 0.0.

### 4.3 Filtering & Resampling
- **Sampling Frequency Validation**: Verify signal sampling rate against `TARGET_FS = 4.0 Hz`. Automatically resample non-4Hz records using polyphase integer-ratio filtering (`scipy.signal.resample_poly`).
- **Filtering**: Apply a **4th-order low-pass Butterworth filter** (cutoff frequency 1.5 Hz) via zero-phase forward-backward filtering (`scipy.signal.filtfilt`).

---

## 5. Clinical Feature Extraction & Rule Engines

### 5.1 Iterative Baseline Estimation
- **Implementation**: Robust iterative mean baseline estimation that excludes accelerations, decelerations, and large signal excursions ($\pm 15$ bpm FIGO window) over 5 iterations, rounded to the nearest 5 bpm.

### 5.2 Deceleration Classification
- **Analysis**: Extract Amplitude, Duration, Onset, Recovery, Shape, and strictly analyze temporal **Relationship to UC** to differentiate *Early*, *Late*, *Variable*, and *Prolonged* decelerations.

### 5.3 Knowledge Rule Engine (FIGO 2015)
- Derived outputs (Normal=0, Suspicious=1, Pathological=2) are stored as **pseudo-labels** (`y_figo`), providing auxiliary supervision during multi-task learning.

---

## 6. Windowing Strategy (Time-Series)

### 6.1 Size and Stride
- **Sliding Window**: Extract **20-minute consecutive windows** ($4,800$ samples at 4 Hz).
- **Clinically Relevant Horizon**: Analysis restricted to the final **60 minutes** before delivery.

### 6.2 Strict Prediction Horizon Labeling
- Fetal distress progresses dynamically during active labor. Labeling early windows from a distress patient as "Distress" introduces weak supervision label noise.
- **Implementation**: Only windows starting within the final **30 minutes** before delivery (`PREDICTION_HORIZON_SAMPLES = 7,200`) receive `y_primary = 1` for distress patients. Windows starting earlier than 30 minutes before delivery receive `y_primary = 0`.

---

## 7. Splitting, Imbalance, and Normalization

### 7.1 Patient-Level Stratified Splitting
- Split the dataset (Train 70% / Val 15% / Test 15%) strictly at the **patient level** before windowing to guarantee zero data leakage.

### 7.2 Class Imbalance Handling (Training Set ONLY)
- **Distress Patients**: 2-minute stride (minority oversampling).
- **Normal Patients**: 10-minute stride (majority undersampling).
- **Validation/Testing Splits**: Fixed 10-minute stride for all patients (unbiased evaluation).

### 7.3 Model Input Normalization
- Baseline correction: $FHR_{\text{norm}} = FHR - \text{Baseline}$.
- **Per-Channel Z-Score Normalization**: Input channels (Baseline-corrected FHR and UC) are normalized to zero mean and unit variance. Scaler mean/std are computed **exclusively on the training split** and applied identically to val/test sets, saved to `data/processed/ctu_signal_scaler.npz`.

---

## 8. Multi-Task Label Generation

Each 20-minute input window is paired with a label vector containing:
1. **Primary Clinical Target (`y_primary`)**: Binary umbilical artery pH $\leq$ 7.15 outcome, enforced strictly within the 30-minute prediction horizon.
2. **Auxiliary Supervisory Targets (`y_figo` & `y_features`)**: FIGO class (0, 1, 2) and 8 continuous physiological descriptors (Baseline, STV, LTV, Accel, Early Decel, Late Decel, Var Decel, Prolonged Decel).
